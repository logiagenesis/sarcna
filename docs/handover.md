## Decisions taken, and why

Where the brief left a choice, or where a literal reading would have produced a
worse result, this is what was decided and why. Change any of them freely.

**1. Fonts: self-hosted Lora and Work Sans, not Fraunces or Inter.**
The brief asked for a warm editorial serif with a clean sans, and said to prefer
self-hosted fonts. Lora and Work Sans are the closest pair available under the
SIL Open Font License that could be embedded directly, so the site makes **no
third-party font requests at all** — better for privacy, page speed and
resilience. Swapping to Fraunces or Playfair later is four `@font-face` blocks
and two variables in `assets/css/app.css`.

**2. Imagery: original illustration, not stock photography.**
The committee does not yet hold licensed venue photography, and the brief
forbids hot-linking. Rather than pass off a stock photo of some other farm as
Boschendal, the site ships original Cape Winelands illustrations generated by
`tools/generate-images.php` — clearly illustrative, unmistakably not a
photograph, in the convention's own palette. Venue images carry a discreet
"ILLUSTRATION · PLACEHOLDER" mark. Every file is listed in
`docs/image-source-log.md` with what should replace it.

**3. A PayFast notification, and nothing else, marks an order paid.**
It would be simpler to mark an order paid when the customer returns to the site.
It would also mean anyone could type a URL and get a free convention
registration. The four-check ITN pipeline costs the customer a minute of
"confirming your payment" and is worth it. This is explained on the page they
see, so it does not read as a fault.

**4. Bed availability is enforced by the database, not by application code.**
A unique index on `(bed_id, active_night)` means two simultaneous checkouts
cannot both take the last bed, no matter what the PHP does. `active_night` is a
generated column that goes `NULL` when a booking is cancelled, so a cancellation
frees the bed with no extra logic.

**5. Shuttle seats are counted at checkout, beds at add-to-cart.**
Beds are individually identified, so they can be held. Seats are a count, so
they are reserved when the order is created and released if payment fails. That
prevents overselling a vehicle while someone is on the PayFast page.

**6. Products that have been sold are deactivated, never deleted.**
Deleting them would break order history. The admin explains this when it
happens.

**7. Secrets live in `.env`, settings live in the database.**
The committee can change the WhatsApp number, the analytics ID, opening and
closing of the shop, and every piece of copy, without touching the server.
Nobody can change the PayFast keys or the SMTP password from a browser.

**8. Policy pages are draft copy in the database.**
They are written for a South African recovery convention — POPIA language,
anonymity provisions, bed-level accommodation terms — and they are editable in
the admin. **They have not been reviewed by a lawyer.** That is a committee
action before launch.

## Known limitations

Stated plainly, so nobody discovers them at an awkward moment.

1. **The PayFast notification requires outbound HTTPS from the server.** If the
   host blocks it, notifications will be rejected as unconfirmed and orders will
   sit unpaid. Check **Admin → Settings → Diagnostics → PayFast reachable**
   before launch. This is deliberate: the site fails closed rather than
   accepting an unverified payment.

2. **Merchandise delivery is not implemented.** The database and admin have the
   flag, but there is no shipping address capture or courier pricing. Everything
   is collected at the registration desk. Adding delivery is a contained piece of
   work if the committee wants it.

3. **No refunds are issued from the site.** Refund in PayFast, then mark the
   order refunded in the admin, which releases the beds and seats. Automating
   refunds would mean holding PayFast API credentials with money-moving rights.

4. **Roommate matching is a request, not an algorithm.** The site records who
   wants to share with whom and shows it on the booking and the rooming list. A
   human decides.

5. **One currency, one language.** ZAR and English only.

6. **Bed holds are released by traffic, not by a scheduler.** Expired holds are
   purged whenever anyone views the cart, the accommodation pages or the admin.
   On a quiet site a hold may sit for a few minutes past its expiry, but it can
   never be double-sold, because the check happens at write time. If the host
   offers cron, calling `/admin` on a schedule tidies it eagerly.

7. **The programme is not a personal schedule.** Attendees see the whole
   timetable; there is no per-person agenda builder.

## For the next developer

The stack was chosen so that whoever comes next can read it. There is no build
step, no framework to learn and no dependency to update. Everything is where its
name says it is.

- Every request enters `public_html/index.php` and is routed by
  `app/Config/routes.php`.
- Business rules live in `app/Services`. Start with `AccommodationService` — it
  is the heart of the thing.
- Controllers are thin. Views are plain PHP.
- Money is always integer cents. `money()` formats it; `rands()` parses it.
- Every dynamic value in a view goes through `e()`.
- Never query without a prepared statement. `Database` makes that the easy path.

Run the lint over everything before you commit:

```bash
find app public_html tools -name '*.php' -exec php -l {} \; | grep -v 'No syntax errors'
```

Silence means everything parses.
